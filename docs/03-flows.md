# 핵심 흐름 (v0)

**범위**: 모드 A(공개 비잠금) + B(공개 잠금).

**작성 원칙**: 각 화면에서 **빈 상태와 실패 상태를 먼저** 정의한다. 이 제품은 정상 경로보다 "아무것도 없는 화면"과 "안 열리는 화면"이 훨씬 자주 보인다. 거기가 잘 안 되면 정상 경로가 아무리 좋아도 소용없다.

---

## 흐름 0 · 둘러본다 (관찰자)

수가 가장 많은 사용자 유형이고, 나중에 작성자가 된다. **랜딩이 곧 피드다.** 설명 페이지를 따로 두지 않는다 — 설명보다 실제 편지가 빠르게 이해시킨다.

### 화면: 피드 (`/`)

```
┌─────────────────────────────────────┐
│  보내지 못한 말               [쓰기] │
├─────────────────────────────────────┤
│  [전체] [옛 연인] [친구] [가족] ...  │
├─────────────────────────────────────┤
│  ┌───────────────────────────────┐  │
│  │ 🔒 잠긴 편지                   │  │
│  │ 2019년 봄, 처음 우산 같이 쓴 날 │  │
│  │              친구에게 · 3일 전  │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 그때 네가 먼저 미안하다고 했는데,│  │
│  │ 나는 자존심 때문에 아무 말도... │  │
│  │            옛 연인에게 · 1일 전 │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

- 잠긴 편지와 열린 편지를 **섞어서** 보여준다. 잠긴 카드가 호기심 엔진이고, 열린 카드가 읽을거리다. 분리하면 둘 다 약해진다.
- 필터 축: 관계 유형. 감정 태그는 v0에서 뺀다 — 작성 시 질문이 하나 늘고, 필터로서의 가치는 아직 미검증.
- 정렬: 최신순. 인기순은 자극적인 편지를 상단에 올려 [D-001](./00-decisions.md)과 충돌한다.
- **위험 등급 '중간' 편지는 여기 안 뜬다** (위협 모델 §2(비공개)). 링크로만 접근된다.

### 빈 상태 — 출시 시점의 실제 문제

편지가 0개인 상태가 반드시 존재한다. [D-007](./00-decisions.md) 때문에 **가짜 편지로 채울 수 없다.**

유일한 해결: 출시 전에 창업자 본인과 초기 참여자가 **실제로 쓴 편지**를 확보한다. 목표 30~50통. 이건 개발 과제가 아니라 출시 전 준비 작업이고, 마일스톤에 항목으로 잡아야 한다.

**빈 화면의 문구는 두 경우가 다르다.** 아래 "이 관계로"는 필터가 걸려 있을 때의 문구다. 필터 없이 0건인 화면에 쓰면 사실과 다르고, 사용자는 필터를 바꾸면 뭔가 있다고 오해한다. 출시 직후 이 화면을 보는 사람이 가장 많다.

편지가 하나도 없는 경우 (필터 없음):

> 아직 남겨진 편지가 없어요.
> [ 첫 편지 쓰기 ]

그럼에도 필터 조합으로 0건이 나오는 경우:

> 아직 이 관계로 쓴 편지가 없어요.
> [ 첫 편지 쓰기 ]

## 흐름 1 · 쓴다

**계정 없음** ([D-004](./00-decisions.md)). 첫 화면부터 본문까지 로그인 요구가 한 번도 없다.

### 1-1. 관계 선택

```
누구에게 보내지 못한 말인가요?

[ 옛 연인 ]  [ 친구 ]  [ 가족 ]
[ 동료 ]     [ 그 외 ]
```

첫 질문을 선택 하나로 두는 이유: 빈 텍스트 상자를 첫 화면으로 던지면 이탈한다. 클릭 한 번으로 시작하면 이미 들어와 있는 상태가 된다.

### 1-2. 본문 작성

- **500자 제한** (가설값). 짧을수록 쓰기 쉽고, 읽기 쉽고, 공유 카드에 담긴다. 실측 후 조정.
- **타이핑 중 필터를 돌리지 않는다.** 실시간 경고는 감시받는 느낌을 주고, 우회 표현을 학습시킨다. 검사는 제출 시 1회.
- **자동 로컬 저장.** 감정 상태에서 쓴 글을 네트워크 오류로 날리면 그 사용자는 돌아오지 않는다.

### 1-3. 모드 선택

```
이 편지를 어떻게 남길까요?

┌──────────────────────────────┐
│ 누구나 읽을 수 있게            │
│ 바로 공개됩니다.               │
└──────────────────────────────┘
┌──────────────────────────────┐
│ 🔒 아는 사람만 열 수 있게      │
│ 단서를 남기고, 답을 아는       │
│ 사람만 열 수 있습니다.         │
└──────────────────────────────┘
```

### 1-4. B 모드 — 단서와 열쇠

**v0에서 문구가 가장 중요한 화면이다.** [D-011](./00-decisions.md)로 자유 텍스트를 허용했으므로, 여기 문구가 S-1(저격)(위협 모델, 비공개) 발생률을 직접 결정한다.

핵심: **지시를 "사람을 특정하라"에서 "순간을 특정하라"로 돌린다.**

```
❌ "이 사람만 알아볼 수 있는 단서를 적어주세요"
✅ "둘만 아는 순간을 하나 적어주세요"
```

전자는 인물을 가리키게 하고, 후자는 사건을 가리키게 한다. 결과물이 다르다.

```
둘만 아는 순간을 하나 적어주세요        (모두에게 보입니다)
┌────────────────────────────────────┐
│ 2019년 봄, 처음 우산 같이 쓴 날      │
└────────────────────────────────────┘
이름 · 학교 · 회사 · 연락처는 쓸 수 없습니다.

그 사람만 답할 수 있는 질문           (모두에게 보입니다)
┌────────────────────────────────────┐
│ 그날 우리가 들어간 카페 이름은?       │
└────────────────────────────────────┘

답                                    (저장되지 않습니다)
┌────────────────────────────────────┐
│                                    │
└────────────────────────────────────┘
```

- 단서와 질문은 **공개된다는 사실을 입력란 옆에 명시**한다. 이걸 안 쓰면 사용자는 비공개라고 착각하고 식별정보를 쓴다.
- 답은 원문 저장 금지, HMAC만 저장 (S-6(위협 모델, 비공개)).
- 답 정규화 규칙(공백 제거·대소문자·자모)은 데이터 모델 문서에서 확정.

### 1-5. 제출 전 확인

**상시 노출 한 줄** (등급 무관):

> 이 편지는 지울 수 있지만, 이미 본 사람의 기억은 지울 수 없습니다.

**등급 중간/높음이면 인터스티셜** (위협 모델 §3(비공개)). 걸린 항목을 정확히 알려주고, 기본 버튼은 `고칠게요`.

### 1-6. 완료

```
편지를 남겼습니다.

[ 공유 카드 ]

이 링크로 언제든 편지를 지울 수 있습니다.
postfeel.kr/manage/xxxxxxxx      [복사]

편지가 열리면 알려드릴까요?
┌──────────────────────────┐
│ 이메일 (선택)             │
└──────────────────────────┘
□ 만 14세 이상입니다
                    [ 등록 ]
```

- 관리 URL에 편지 ID를 넣지 않는다 — 토큰만으로 식별한다 ([D-014](./00-decisions.md)).
- **연령 체크박스는 이메일을 넣을 때만 필수다.** 이메일 칸이 비어 있으면 체크박스도 숨긴다. 미체크 상태에서는 `등록`이 비활성이고, 서버도 거부한다 ([D-013](./00-decisions.md), [API §3](./05-api.md)).
- 등록은 편지 ID가 아니라 **방금 받은 관리 토큰으로** 보낸다. 이 화면은 이미 토큰을 갖고 있어 사용자에게는 차이가 없다 ([API §3](./05-api.md)).
- 이메일 없이 넘어가는 게 정상 경로다. 건너뛰기를 눈에 띄게 둔다.
- 관리 링크를 "저장하세요"라고만 하면 대부분 저장하지 않는다. 이메일 입력이 실질적인 백업 경로다 ([D-005](./00-decisions.md), [D-013](./00-decisions.md)).
- 이메일은 **여기서만** 요구한다. 이 시점의 사용자는 이미 가치를 만든 상태다.

### 실패 상태

| 상황 | 처리 |
|---|---|
| 등급 '높음' 차단 | 걸린 항목 명시. **본문은 1-2의 로컬 초안으로만 보존** — 서버에는 저장하지 않는다([데이터 모델 「저장하지 않는 것」](./04-data-model.md)). 재작성 강요 금지 |
| 차단 사유에 `self_harm`이 있음 | 위 차단 화면에 **위기 상담 안내**를 함께 띄운다 (아래) |
| 네트워크 오류 | 로컬 초안 유지, 재시도 버튼 |
| 레이트리밋 | 정상 사용자가 걸리면 안 되므로 임계를 높게. 걸리면 대기 시간 명시 |

### 1-6-1. 위기 상담 안내 (`self_harm`으로 차단됐을 때)

S-4(위협 모델, 비공개)가 요구하는 유일한 조치다. **별도 페이지를 만들지 않고 차단 화면 안에** 띄운다 — 이미 그 화면에 있는 사람을 다른 데로 보내지 않는다.

```
이 편지는 올릴 수 없습니다.
(걸린 항목 안내)

지금 많이 힘드시다면 이야기할 수 있는 곳이 있습니다.

  자살예방상담전화   109         24시간
  정신건강상담전화   1577-0199   24시간

              [ 편지 고치기 ]
```

- **기관 · 연락처 · 운영시간은 출시 전에 실제로 확인해서 채운다.** 틀린 번호를 넣는 건 안내를 안 하는 것보다 나쁘다 → [출시 게이트](./08-milestones.md) 항목
- **위 값의 출처**: 보건복지상담센터 <https://www.129.go.kr/109> (확인일 2026-08-14). 2024년 1월 1일부터 흩어져 있던 자살예방 상담번호가 **`109`로 통합**됐다 — 통합 전 네 자리 번호는 쓰지 않고, 이 문서에도 적지 않는다(적어두면 복사해 간다). 코드의 값은 `src/lib/crisis.ts`에 있고 근거도 그 파일 상단에 있다
- 우리는 안내만 한다. 상담 채널을 사칭하지 않고, 대신 연락하지 않고, 응답을 받지도 않는다 ([D-001](./00-decisions.md) · [운영 §4](./07-operations.md))
- 차단이므로 **본문은 여기서도 서버로 가지 않는다**
- 오탐이어도 띄우는 쪽으로 기운다 (위협 모델 S-4(비공개))

### 1-7. 관리 화면 (`/manage/:token`)

관리 링크로만 접근. 삭제뿐 아니라 **현재 상태를 보여주는 화면**이다.

**편지가 비공개 상태여도 이 화면은 열린다.** 이게 이의 제기의 유일한 경로다 ([표면별 응답](./05-api.md)).

```
이 편지는 신고가 접수되어 현재 비공개 상태입니다.
검토 중이며, 보통 하루 안에 결과를 알려드립니다.

[ 이의 제기 ]        [ 편지 삭제 ]
```

이메일을 남기지 않은 작성자는 자기 편지가 내려간 사실을 알 방법이 여기밖에 없다. 위협 모델 §4(비공개)가 요구한 이의 제기 경로가 이것이다 ([데이터 모델 §5 발견 2](./04-data-model.md)).

## 흐름 2 · 연다

### A 모드

카드를 누르면 본문이 보인다. 끝. 별도 화면 없음.

### B 모드

```
┌─────────────────────────────────────┐
│ 🔒                                   │
│ 2019년 봄, 처음 우산 같이 쓴 날       │
│                    친구에게 · 3일 전  │
├─────────────────────────────────────┤
│ 그날 우리가 들어간 카페 이름은?        │
│ ┌─────────────────────────────────┐ │
│ │                                 │ │
│ └─────────────────────────────────┘ │
│              [ 열어보기 ]            │
│                    남은 시도 3번     │
└─────────────────────────────────────┘
```

- **오답 시 어떤 정보도 주지 않는다.** 글자 수, 부분 일치, 오답 메시지 차이 전부 금지 (S-6(위협 모델, 비공개)).
- 남은 시도 횟수는 **보여준다** — 브루트포서에게는 이미 알려진 정보이고, 일반 사용자에게는 필요한 정보다.
- 실패할수록 지연 증가.
- 시도 소진은 영구 차단이 아니라 **시간 기반 회복**. 진짜 수신자가 한 번 틀렸다고 영영 못 여는 건 제품 실패다.
- **한 번 연 편지는 재방문해도 바로 열린다.** 다시 맞히게 하면 시도 3회를 재소모해서, 자기에게 온 편지를 다시 보러 온 사람이 못 여는 상황이 생긴다. 쿠키로 기억한다 ([데이터 모델 §4](./04-data-model.md)).

### 열람 성공 후

본문을 먼저 보여주고, **다 읽은 뒤에** 한 번만 묻는다:

```
이 편지, 당신에게 온 것 같나요?

[ 나에게 온 것 같아요 ]  [ 아닌 것 같아요 ]  [ 모르겠어요 ]
```

이게 북극성 지표의 유일한 수집 지점이다 ([제품 정의](./01-product.md)). 읽기 전에 띄우면 방해가 되고, 응답도 부정확해진다.

### "아닌 것 같아요"가 가장 흔한 결과다

빈 상태 설계에서 제일 중요한 지점이다. 잠긴 편지를 여는 사람 대부분은 의도한 수신자가 아니다. 여기서 나가면 루프가 끊긴다.

```
그럼 이 편지는 아직 주인을 기다리는 중이에요.

[ 다른 편지 보기 ]     [ 나도 남기기 ]
```

### 작성자 알림

이메일을 남긴 경우에만 나간다. 편지가 처음 열리면 "누군가 열었습니다"([D-007](./00-decisions.md)), 연 사람이 `yes`로 답하면 "편지를 연 사람이 '나에게 온 것 같다'고 답했습니다"([D-023](./00-decisions.md)). 둘 다 편지당 1회다.

두 문구 모두 주어가 **"편지를 연 사람"**이다. `상대가 읽었습니다` · `상대가 편지를 받았다고 확인했습니다`가 아니다 — 열쇠를 맞춘 사람이 의도한 상대라는 보장이 없다. 발송 조건과 문구는 [발송 §2](./09-notifications.md).

## 흐름 3 · 공유한다

[D-006](./00-decisions.md)에 따라 **공유가 유일한 배달 수단**이다. 여기는 부가 기능이 아니라 유통 인프라다.

### 공유 카드 (OG 이미지)

카카오톡 링크 미리보기가 한국에서 사실상 유일한 유입 경로다. 카드가 곧 광고다.

| 모드 | 카드에 담기는 것 |
|---|---|
| A | 본문 일부 + 관계 유형 |
| B | **단서만** + 🔒 + 관계 유형 |

B 모드 카드에 단서를 넣는 건 안전상 문제없다 — 단서는 이미 피드에 공개되는 정보다.

### 공유 문구를 우리가 제안한다

사용자가 "뭐라고 하면서 보내지"에서 막히면 공유하지 않는다. 복사 버튼과 함께 문구를 준다.

```
혹시 너한테 온 거 아니야?
postfeel.kr/m/xxxx
```

### 검색엔진

- **개별 편지 페이지: `noindex`** (크롤링은 허용 — 안 그러면 `noindex`를 읽지 못한다)
- 피드 목록 페이지: 색인 허용

S-10(위협 모델, 비공개) — v0에서 유일하게 사후 조치가 불가능한 항목이므로 첫 배포부터 켠다.

## 화면 목록 (v0)

| 경로 | 화면 | 비고 |
|---|---|---|
| `/` | 피드 (= 랜딩) | 색인 허용 |
| `/write` | 작성 (관계 → 본문 → 모드 → 단서 → 확인) | 단일 페이지 다단계 |
| `/m/:id` | 편지 열람 (A는 본문, B는 잠금) | **noindex** |
| `/manage/:token` | 작성자 — 상태 확인, 이의 제기, 삭제 | 랜덤 토큰, 편지 ID 미포함 |
| `/report/:id` | 신고 | 2번 이내 조작으로 도달 |
| `/delete-request` | 관리 링크 분실 시 삭제 요청 | 본문 일부 대조 |
| `/unsubscribe/:token` | 알림 해지 결과 | 확인 없이 즉시 해지 ([발송 §1](./09-notifications.md)) |
| `/admin` | 운영자 — 킬 스위치, 직접 비공개, 큐 링크 | |
| `/admin/queue` | 운영자 — 신고 · 자동 비공개 건 · 이의 제기 · 삭제 요청 큐 | 판정은 여기서 한다 ([운영 §1 · §2](./07-operations.md) · [발송 §3](./09-notifications.md)) |
| `/terms`, `/privacy` | 약관·처리방침 | 최소 연령 명시. **모든 화면 아래 푸터에서 도달한다** — 공용 레이아웃의 링크 두 개가 유일한 경로다 |

> `/admin`과 `/admin/queue`는 인증되지 않으면 로그인 폼으로 교체된다 ([API §4](./05-api.md))
> — 큐 화면에는 신고당한 편지의 **본문**이 뜬다.
