# 마일스톤 & 출시 게이트 (v0)

## 소요 시간을 적지 않는 이유

작성자의 실제 작업 속도를 관측한 적이 없다. 근거 없는 주간 추정치는 계획처럼 보이지만 계획이 아니다.

대신 각 마일스톤에 **완료 판정 기준**을 붙였다. "됐다"를 감으로 정하지 않기 위해서다. 상대 크기(S/M/L)만 참고용으로 표시한다.

## M0 · 법률 확인 (코딩 아님) `S`

**M1보다 먼저 한다.** 법률은 출시 게이트만 막고 개발은 막지 않지만, **[L-007](./00-decisions.md)의 답이 스키마와 삭제 동작을 바꿀 수 있다** — 완전 삭제라면 지금의 soft delete로 부족하고, 보존이라면 격리 보관 위치가 필요하다. 나중에 확인하면 그 부분을 다시 만들게 된다.

**확인 대상**: [L-001 · L-002 · L-006 · L-007](./00-decisions.md).

**질문서는 [`m0-legal-questions.md`](./m0-legal-questions.md)에 있다.** 상담 자리에 그대로 들고 가는 문서다 — 아래 준비물 표를 사실관계 절로 펼쳐 쓰고, 넷을 검증 가능한 질문 형태로 나눴다. 코드에서 뽑은 값이므로 상담 전에 코드가 바뀌었으면 다시 뽑는다.

**상담 전에 준비해 갈 것** — 질문이 구체적일수록 답이 쓸모 있다.

| 가져갈 것 | 어디에 있나 |
|---|---|
| 수집하는 개인정보 전체 목록 | 이메일 1종뿐 ([D-005](./00-decisions.md)) + `fp_hash`(IP·UA 해시) + 해지한 주소의 `sha256`([발송 §1](./09-notifications.md)) |
| 저장하지 않는 것 목록 | [데이터 모델 「저장하지 않는 것」](./04-data-model.md) |
| 보관 기간 | 편지 무기한 ([D-024](./00-decisions.md)), `session_id` 90일, `fp_hash` 미정 |
| 연령 처리 방식 | 이메일 입력 시점 체크박스 1개, 서버 강제 ([D-013](./00-decisions.md)) |
| 삭제 경로 3종 | 작성자 삭제 · 운영자 조치 · [삭제 요청 폼](./07-operations.md) |

**L-007에 대해 구체적으로 물을 것**: 미성년 관련 성적 콘텐츠를 내렸을 때 (1) 본문을 즉시 완전 삭제해야 하는가, (2) 신고·수사 대응을 위해 보존해야 하는가, (3) 보존한다면 어디에 어떤 형태로 얼마나. **답에 따라 M1 스키마가 달라진다.**

> 이 문장은 **경로 하나만** 물었다. 구현이 드러낸 두 번째 경로가 있다 — 자동 검사가 `high`로 막으면 **본문이 애초에 저장되지 않는다**(04 「저장하지 않는 것」). 즉 "내렸을 때"의 앞단에 "아예 남기지 않았을 때"가 따로 있고, 보존 의무가 있다면 그쪽이 먼저 문제가 된다. 질문서 [Q1-a](./m0-legal-questions.md)가 이 경로를 따로 묻는다.

**완료 판정**: 넷 다 답을 받았고, 그중 스키마·삭제 동작에 영향을 주는 항목이 M1 착수 전에 반영됐다.

> **답은 받았지만 완료 판정의 뒷부분은 지키지 못했다.** M1~M5를 먼저 만들고 M0를 나중에 받아서, 이 절이 맨 앞에서 경고한 그대로 **삭제 동작과 스키마를 다시 만들게 됐다.** 그 작업이 [M7](#m7--m0-답-반영-l)이고, 순서를 지켰다면 M7의 4번이 없었다.

## M1 · 기반 `L`

- Next.js(App Router) + TypeScript + Postgres 세팅 — Vercel + Supabase ([D-018](./00-decisions.md))
- 시크릿 주입: `answer_key` · `fp_key` ([D-017](./00-decisions.md)). **`answer_key`는 편지가 쌓인 뒤에는 못 나눈다.** `confirmation_key` · `admin_session_key`는 쓰기 시작하는 M2에서 추가한다 (D-017 시크릿 목록)
- [스키마 전체](./04-data-model.md) 마이그레이션
- 편지 생성 **(A 모드만)**, 단건 조회, 피드
- 관리 링크 발급 · 삭제
- **`noindex`** · **킬 스위치**

> `noindex`와 킬 스위치를 M1에 넣는 이유: 스테이징이라도 공개 URL이면 색인될 수 있고, S-10(위협 모델, 비공개)은 v0에서 유일하게 사후 조치가 불가능한 항목이다. 킬 스위치는 나중에 붙이면 정작 필요한 첫 사고 때 없다.

**완료 판정**
1. 편지를 쓰면 피드에 뜬다
2. 관리 링크로 지우면 피드·직접 조회·OG 전부 404 ([안전 테스트 10](./05-api.md)의 `deleted_by_author` 부분 — `hidden_auto`·`hidden_admin`은 M2에서 생긴다)
3. `/m/:id` 응답에 `noindex` 헤더가 있다 (테스트 9)
4. `public_read_enabled=false`로 피드 · 직접 링크 · OG가 전부 즉시 꺼지고, `/manage/:token`은 계속 동작한다 (테스트 15)

## M2 · 안전 `L`

- 정규식 + 사전 필터 — 연락처 · URL · 학교 · 회사. **정규화 후 재매칭**(공백·특수문자·자모 분리 우회 대응)
- 위험 등급 3단계(위협 모델, 비공개) + [`confirmation` 토큰](./05-api.md)
- 인터스티셜
- 신고 → 자동 비공개 → `/admin` 큐 → 판정 · 복구
- `/admin` 로그인 (비밀번호 + 쿠키 세션) · **심각 카테고리 텔레그램 알림** ([발송 §3](./09-notifications.md))
- LLM 분류기 ([D-020](./00-decisions.md)) — OpenAI `gpt-5.6-luna`, effort `none|low`, **JSON 스키마 강제 출력**
- **거부(`refusal`) → `high`** — 실패와 다른 경로다. 거부를 `medium` 강등으로 흘리면 S-4·S-5가 게시된다
- 인터스티셜 문구(`notice`)를 같은 호출에서 받기 — 왕복 추가 없음
- 신고 큐 초안 판정 ([운영 §2](./07-operations.md)) — 조치 버튼은 붙이지 않는다
- **분류기 실패 경로** ([D-015](./00-decisions.md)) — 타임아웃 3초, 재시도 1회, `medium` 강등
- **재분류 잡** — `classifier_state = 'unavailable'` 편지를 10분마다 재시도. 이게 없으면 장애 1시간이 그 시간대 편지를 영구히 피드에서 제외한다
- **이의 제기 처리** — `restore` / `reject`. 접수만 되고 결론이 없으면 이의 제기 경로가 아니다
- **위기 상담 안내** — `self_harm` 차단 화면 안에 ([흐름 1-6-1](./03-flows.md), [D-026](./00-decisions.md)). 기관·연락처는 M6에서 채운다
- **심각 카테고리는 `auto_hide_exempt`를 뚫는다** ([D-025](./00-decisions.md)) — `reason in ('doxx','sexual','selfharm')`

> 분류기 없이 M3로 넘어가도 되지만, **출시 게이트에는 포함된다.** 정규식만으로는 S-1(저격)(위협 모델, 비공개)이 거의 안 걸리고, 그러면 인터스티셜이 뜨지 않아 v0 최대 방어가 작동하지 않는다.

**완료 판정**
1. 전화번호·URL이 든 편지는 게시되지 않는다
2. [안전 테스트](./05-api.md) 3 · 4 · 7 · 8 · 10 · 11 · 12 · 13 · 21 · 22 통과 (10은 `hidden_auto`·`hidden_admin`이 생기는 여기서 전부 검증된다. 14 · 17은 이메일 등록 엔드포인트를 재는 것이라 M4)
3. 신고 → 자동 비공개 → `dismiss` → 재신고해도 안 내려감(`auto_hide_exempt`). 단 심각 카테고리로 재신고하면 내려간다 (테스트 8)
4. 분류기를 끈 상태로 편지를 쓰면 `medium`으로 생성되고, 되살리면 재분류 잡이 등급을 갱신한다

## M4 · 유통 `M`

**[D-006](./00-decisions.md)에 따라 공유가 유일한 배달 수단이다. 여기가 부가 기능이 아니다.**

- OG 카드 (A: 본문 일부 / B: 단서만)
- 공유 문구 + 복사 버튼
- 완료 화면 — 관리 링크, 이메일 선택
- **이메일 4종 + 해지 링크** ([발송 §2](./09-notifications.md))
- 이메일 등록 엔드포인트 `POST /api/manage/:token/contact` — 연령 체크 서버 강제 ([API §3](./05-api.md))
- **해지 억제 목록** `email_suppressions` ([발송 §1](./09-notifications.md)) — 해지한 주소가 재등록되면 D-006 방어가 한 번 쓰고 사라진다
- **"아닌 것 같아요" 이후 화면** ([흐름 §2](./03-flows.md))

**완료 판정**
1. **실제 카카오톡에 링크를 붙여 미리보기를 눈으로 확인** — 개발자 도구로는 검증되지 않는다
2. B 모드 카드에 본문이 없다 (테스트 2), 어떤 메일에도 본문이 없다 (테스트 20), 4번 메일이 `yes`에만 나간다 (테스트 24)
3. 해지 링크를 누르면 이후 발송이 없고 (테스트 18), "누군가 열었습니다"는 편지당 한 통이다 (테스트 19)
4. 관리 토큰 없이는 이메일을 등록할 수 없고, `ageConfirmed`가 없으면 저장되지 않는다 (테스트 14 · 17)
5. 열람 후 "아닌 것 같아요"에서 피드/작성으로 가는 경로가 있다

## M6 · 출시 전 (코딩 아님) `M`

이 단계를 개발 일정에 안 넣으면 출시가 밀린다.

- **실제 편지 30~50통 확보.** [피드 빈 상태](./03-flows.md)는 코드로 못 푼다. [D-007](./00-decisions.md) 때문에 가짜로 채울 수 없다
- 약관·개인정보처리방침 — M0 답 반영은 [M7](#m7--m0-답-반영-l)에서 끝났다. **남은 것은 배포로 값이 생기는 넷**: 보호책임자 명칭 · 전용 이메일 · 권익침해 구제기관 연락처 · 시행일
- **위기 상담 안내의 기관·연락처·운영시간 확인** ([흐름 1-6-1](./03-flows.md)) — 틀린 번호는 안내를 안 하는 것보다 나쁘다
- 운영 리허설: 직접 신고하고, 판정하고, 복구하고, 킬 스위치를 눌러본다
- 백업 · 복구 확인

## M7 · M0 답 반영 `L`

[M0 답](./00-decisions.md)이 v0 코드의 전제를 여럿 뒤집었다. M1~M5 위에 얹히는 단계이고, 새 결정은 [D-027 ~ D-035](./00-decisions.md)다. **근거는 전부 그 항목들에 있다 — 여기는 무엇이 만들어졌고 무엇이 남았는지만 적는다.**

### 만들어진 것

|---|---|---|
| 완전 파기 + tombstone | `migrations/0003` · `letters/deletion.ts` | 25 |
| 법정 접속기록 (분리 스키마 · 봉인 · 조인 키 없음) | `migrations/0004` · `lib/access-log.ts` · `middleware.ts` | 26 |
| 30일 암호화 격리 (심각 카테고리만) | `migrations/0005` · `letters/deletion.ts` | 27 |

문서도 함께 맞췄다 — `04`(저장하지 않는 것 · 상태 기계) · `07`(§3 세 번째 스위치 · §4 L-007 처리와 112 · §6 수사기관 · §7 점검 둘) · `/privacy` · `/terms`.

> **화면 문구는 코드보다 먼저 고치지 않는다.** `/privacy`·`/terms`는 "지금 코드가 하는 일"만 적는 파일이라, 동작보다 먼저 바꾸면 **하지도 않는 수집을 한다고 고지하는 꼴**이 된다. 지어낸 조항을 쓰지 않기로 한 것과 방향만 반대인 같은 잘못이다.

### 남은 것 셋

**1. O-009 · 층 2 모델 선정** — 가장 많이 막는다 (게이트 6 · 14 · 18).

[D-029](./00-decisions.md)가 방향만 정했다. 고르는 절차는 [등급 사다리](#이-게이트가-모델-등급도-정한다)와 같다 — **감으로 고르지 않는다.**

```
후보 스크리닝 → 추론 리전이 국내인가        (아니면 탈락. 저장 리전만으로는 안 된다)
             → JSON 스키마 강제 출력이 되는가 (05-api §1이 요구한다)
             → 지연이 3초 예산에 들어오는가
             → 평가셋 v2로 재현율·오탐율 판정
```

후보 조사와 남은 확인 다섯은 [`o-009-classifier-candidates.md`](./o-009-classifier-candidates.md)에 있다.

**완료 판정**: 모델이 정해졌고, 추론 리전이 국내라는 근거가 문서에 있고, 판정 결과가 [`eval/README.md`](../eval/README.md)에 실행 기록으로 남았다.

**2. O-010 · DB 저장 리전** — [D-034](./00-decisions.md) 2번. Supabase에서 국내 리전이 되는지 확인하고, 안 되면 사업자를 교체한다.

**완료 판정**: 리전이 정해졌고 [D-018](./00-decisions.md)이 그에 맞게 갱신됐다.

**3. 평가셋 v2 검토** — 민감정보 사례를 더해 64건(위험 32 / 정상 32)이 됐으나 **문장 검토가 안 끝났다.** 오탐율 임계값 0.2도 [D-033](./00-decisions.md)의 "판단 불가 시 차단"과 함께 다시 본다 — 다만 **실측 없이 숫자를 바꾸지 않는다.**

**완료 판정**: 사용자 문장 검토가 끝났고, `dataset.ts` 상단의 "승인 전까지 게이트 판정 근거로 쓰지 않는다"가 지워졌다.

### "분류기 동작"의 합격 기준

"동작한다"를 감으로 판정하면 게이트가 게이트가 아니다. **고정 평가셋으로 판정한다.**

- 편지 예시 **64건**을 직접 작성하고 정답 라벨을 붙인다 — **위험 32 / 정상 32.** 1:1을 유지한다: 위험 쪽만 늘리면 두 임계값이 서로 다른 표본을 재게 된다
- 위험 32건은 S-1(저격)(위협 모델, 비공개) · S-2(신상)(위협 모델, 비공개) 유형(인명 · 학교 · 회사 · 연락처 · 특정 가능한 조합) **25건 + [D-033](./00-decisions.md)의 민감정보 7범주 7건**
- 정상 32건은 실제로 쓸 법한 편지. 민감정보 대응 7건은 **같은 어휘에 주어만 다르다**(본인 이야기 · 일반론 · 비유) — 범주 자체가 아니라 "제3자의 것인가"를 재기 위해서다
- 각 건에 **"층 1이 잡을 수 있는 유형인가"**를 함께 라벨링한다. 이게 없으면 아래 층별 집계가 안 나온다

**"탐지"는 판정 등급이 `medium` 이상인 것이다.** 등급은 3단계인데 라벨은 이진이라 이 정의가 없으면 재현율을 계산할 수 없었다. `medium`도 피드에서 빠지므로 S-1(위협 모델, 비공개)의 주 피해 경로(불특정 다수 노출)는 막힌 것으로 본다. 오탐도 같은 기준이다 — 정상 편지가 `medium` 이상을 받으면 오탐이다.

| 기준 | 임계값 | 왜 |
|---|---|---|
| 위험 재현율 (recall) | **≥ 0.8** | 놓치는 게 훨씬 비싸다 |
| 정상 오탐율 | **≤ 0.2** | 오탐은 피드에서 빠질 뿐이라 비용이 낮다 |

**측정 대상은 층 1 + 층 2 파이프라인 전체다.** 게이트가 판정할 질문은 "luna가 잘하나"가 아니라 "이 시스템이 저격을 거르나"이기 때문이다. 다만 결과는 반드시 **층별로 나눠 집계한다**:

```
탐지된 건  → 층 1이 잡음 / 층 2가 잡음
놓친 건    → 둘 다 놓침
```

묶어서 한 숫자만 보면 층 1의 정규식이 연락처·URL을 쓸어담아 재현율을 밀어올리고, **한국어 인명·맥락을 못 잡는 모델도 0.8을 넘길 수 있다** — [D-020](./00-decisions.md)이 "모른다"고 적어둔 바로 그 능력이 가려진다.

**재현율을 정밀도보다 우선한다.** medium 오탐의 비용은 "피드에 안 뜬다"이고, 미탐의 비용은 "저격 편지가 그대로 게시된다"이다. 대칭이 아니다.

평가셋은 리포에 커밋하고, 필터를 고칠 때마다 다시 돌린다. 임계값 0.8 / 0.2는 가설값이다. **배치로 돌린다** — 제출 경로가 아니라 지연이 무관하고 단가가 절반이다.

### 이 게이트가 모델 등급도 정한다

[D-020](./00-decisions.md)은 `gpt-5.6-luna`로 시작한다. 한국어 인명·맥락 판정에 luna가 충분한지는 **모른다.** 평가셋이 그 판정 절차다:

```
luna + effort low  → 전체 재현율 ≥ 0.8?  → 통과. 그대로 간다
                   → 미달                → effort 올려 재측정
                                         → 그래도 미달이면 terra (입력 10배)
```

**게이트를 막는 임계값은 전체 수치 하나뿐이다.** 층별 집계는 임계값이 아니라 **모델 교체 판단의 근거**다 — 전체가 0.8을 넘겼더라도 층 2 전용 유형(인명·맥락)에서 놓친 건이 있으면 그 수를 기록해두고 아래 W3–4 튜닝에서 다시 본다. 층 2에 별도 임계값을 지금 정하지 않는 이유는 실측값이 없어서다. 숫자를 지어내면 게이트가 아니라 장식이 된다.

**모델을 감으로 고르지 않는다.** 그러라고 평가셋을 먼저 만든다. 등급을 올리면 §비용 상한도 함께 다시 본다.

## 출시 후 4주

### W1 — 지인 20~30명

지표를 보지 말고 **사람을 관찰한다.**

특히 **안 쓴 사람에게 직접 묻는다.** 쓴 사람보다 정보량이 많다. "왜 안 썼어?"의 답이 무섭다 / 귀찮다 / 뭘 쓸지 모르겠다 / 남이 볼까 봐 중 무엇인지에 따라 고칠 곳이 완전히 다르다.

### 공유 문구

원래 계획했던 문구는 쓰지 않는 게 좋다.

```
❌ "최근에 헤어진 친구 있으면 이거 보내"
```

상대를 "위로가 필요한 사람"으로 분류하는 말이라, 받는 쪽이 불쾌해질 수 있고 서비스가 이별 감정을 이용한다는 인상을 준다.

```
✅ "전하지 못한 말 남겨두는 데야. 잠가서 올리면 아는 사람만 열 수 있어."
```

제품이 무엇인지만 말하고 상대의 상태를 규정하지 않는다.

### W2 — 첫 방어 점검

전환 트리거 5개(위협 모델, 비공개) 첫 대조. 이 시점에 이미 걸리면 확산을 멈추고 고친다.

### W3–4 — 확산과 튜닝

- 인터스티셜 회귀율을 보고 문구 수정
- 등급 `medium` 오탐률을 보고 필터 조정
- 본문 500자 / 시도 3회 실측 후 조정

**신고율이 3%를 넘으면 확산을 멈춘다.** 이 시점의 트래픽 증가는 성장이 아니라 위험 사용 사례의 확산일 수 있다.
